# Pitfalls / known issues

- **Chrome `--virtual-time-budget` desync (2026-10-21):** headless Chrome fast-forward runs the virtual clock ahead of chained `setTimeout` timers. Symptom: `tb-lastpkt` shows ~10–11 s in virtual-time DOM dumps while cards keep updating (simulator alive). This is a harness artifact, not an app bug — in real time both advance together (~1 s). For ground truth, run the page in real time (user's browser) or a CDP driver with a real-time wait.
- **Classifier blocks `--remote-debugging-port`** on this machine's auto-mode; `--screenshot` and `--dump-dom` headless invocations are allowed.
- ES modules require HTTP serving (`file://` breaks module loading) — `python3 -m http.server 8000` from `interface/`.
- **CDP debugging attempt (2026-10-22):** `test-step6.js` / `debug-search.js` / `verify-step6.js` (in `interface/`) drove Chrome via `--remote-debugging-port` + the `ws` package. Consistent with the blocked-port pitfall above, they were never confirmed to run. Deleted 2026-10-22.
- **npm cruft (2026-10-22):** `package.json` + `package-lock.json` + `node_modules/ws` existed at BOTH the repo root and `interface/`, installed only for those CDP scripts. The dashboard itself stays dependency-free. As of this session they were moved to `_cruft-2026-10-22/` at the repo root (auto-mode blocked `rm` on them) — removed 2026-11-06; the directory no longer exists.
- (2026-10-22, superseded) Dashboard sources, `AGENTS.md`, `.gitignore` and `.claude/memory/` are all committed on `feature/ground-station` (commit `55e3a65`); `.gitignore` excludes `.DS_Store`, `node_modules/`, `_cruft-2026-10-22/`, `report_screenshots/`.
- **WS text vs binary frames (2026-10-25, S2):** the `websockets` library sends a *binary* frame when `send()` is given `bytes`, and a *text* frame when given `str`. The dashboard's `link.js` does `JSON.parse(e.data)` expecting a **text** frame; a binary frame arrives as a `Blob` and `JSON.parse` throws `[link] bad frame … "[object Blob]" is not valid JSON`. Fix: `protocol.encode_ws_message` must return `str` (not `bytes`). Symptom when wrong: top-bar link chip shows LINK (connection is open) but all telemetry cards stay "—" because every frame is dropped as a bad frame.
